# CoopTown サイト連携 BP

Web ポータルサイトとゲームをつなぐビヘイビアパックです。本体アドオン（CoopTown_BP）とは別のパックで、
サイトとの通信・API キー・ベータ API が必要なのはこのパックだけです。本体アドオンはこのパックがなくても動きます。

- **BDS 専用**です（`@minecraft/server-net` は BDS でしか動きません）。
- 対象：BDS **1.26.5x**（2026年10月時点の最新正式版）
  - `@minecraft/server` 2.11.0-beta
  - `@minecraft/server-net` 1.0.0-beta
  - `@minecraft/server-admin` 1.0.0-beta
- ベータ版のモジュールは、BDS を更新するたびにバージョンが変わります。BDS を更新したら `manifest.json` の
  `dependencies` を新しいバージョンに合わせてください。合っていないとコンテンツログにエラーが出て、パックが読み込まれません。

## ファイル

| ファイル | 役割 |
|---|---|
| `scripts/main.js` | 起動。各機能を順に動かす（1つが失敗しても他は動く） |
| `scripts/config.js` | 間隔・上限などの設定と、本体との約束事の名前 |
| `scripts/http.js` | サイトへの送受信と再送キュー（失敗した送信をワールドに保存して後で再送） |
| `scripts/store.js` | ワールドのダイナミックプロパティへの保存（長いものは分割） |
| `scripts/link.js` | `!link コード` で Discord と連携 |
| `scripts/players.js` | 60秒ごとのプレイヤー情報、退出時の `online:false` |
| `scripts/bestiary.js` | 個人図鑑（出会った・倒した） |
| `scripts/quests.js` | 依頼の差分取得と、お金の指示（預かり・支払い・返金） |
| `scripts/town.js` | 街の状態の送信 |
| `scripts/logs.js` | 行動ログ（参加・退出・死亡・チャット） |
| `scripts/discord.js` | ゲームの出来事を Discord のチャンネルへ投稿（Webhook） |
| `bds-config/` | BDS の設定ファイルの例 |

## 導入手順

1. ワールドに **本体アドオン（CoopTown_BP / CoopTown_RP）** と **このパック** の両方を入れます。
2. ワールドの実験的機能で **「ベータ API」をオン**にします。
3. BDS の `config/default/` に設定ファイルを置きます（`bds-config/` の例をコピーして書き換え）。
   - `permissions.json`：`allowed_modules` に `@minecraft/server-net` と `@minecraft/server-admin` を入れる
   - `variables.json`：`portal_url` にサイトの URL（末尾の `/` は不要）
   - `secrets.json`：`game_api_key` に **`Bearer ` を含めた**キー（例 `"Bearer abcdef..."`）
   - API キーはコードには書いていません。`secrets.json` は人に見せないでください。
4. BDS を起動し、コンテンツログに `[Portal] サイト連携を開始しました（設定：OK）` と出ることを確認します。
   「未設定」と出たら、`variables.json` と `secrets.json` の場所と名前を確認してください。

## 動きのまとめ

- **プレイヤー ID**：サイトに送る `xuid` には、すべての API で `player.id` を使います。
- **通信の失敗**：サイトは休止することがあるので、失敗前提で作っています。
  - 依頼の作成・状態変更、街、退出、行動ログは、ワールドに保存して再送します（間隔は5秒から倍々で最大5分）。
  - `400` `404` `409` は、同じ内容を送っても直らないので再送しません。理由はコンテンツログに出ます。
  - プレイヤー情報は再送しません。次の60秒で新しい値を送ります。
  - 図鑑は、サイトが受け取るまで未送信リストに残ります。
  - 連携（`!link`）は自動で再送しません。本人に再入力をお願いするメッセージを出します。
- **負荷**：同時に飛ばすリクエストは2本までです。図鑑の「出会った」は、2秒ごとに3人ずつ周りを調べます。

### 依頼のお金（二重払いを防ぐしくみ）

サイトはお金を動かしません。お金を増減するのは本体アドオンだけで、このパックは scriptevent で指示を出します。

| 依頼の状態 | このパックがやること |
|---|---|
| `open`（まだ預かっていない） | 本体に「預かり」を指示。残高不足ならサイトに `cancel`（依頼主）を報告 |
| `accepted` | 受注者と依頼主に通知（オンラインなら） |
| 納品を確認（本体から `portal:delivered`） | サイトに `complete`（受注者）を報告 |
| `done`（まだ支払っていない） | 本体に「受注者へ支払い」を指示 |
| `cancelled`（預かり済み・未返金） | 本体に「依頼主へ返金」を指示 |

- 依頼ごとの指示の状況（処理中・済み・失敗）をワールドのダイナミックプロパティに記録します。「済み」「失敗」の指示は、
  同じ依頼が何度届いても二度と出しません。
- 本体から返事がない「処理中」の指示は、1分ごとと再起動直後にもう一度出します。本体は同じ依頼・同じ操作を
  1回しか実行しない（2回目以降は最初の結果を返す）ので、何度出しても二重にはなりません。
- 報酬 0 の依頼は、預かり・支払い・返金をしません。
- 預かれないまま `accepted` や `done` になった依頼（運営がサイトで直接操作した場合など）は、支払いをせず、
  コンテンツログに警告を出します。

## アドオン間の約束事

**本体 → 連携（スコアボード・タグ。本体が5秒ごとにオンラインの人へ書き込む）**
- スコアボード：`lv_player` `lv_gather` `lv_mine` `lv_craft` `money`（所持金。銀行の預金は含まない）
- タグ：`job_main:<ID>` `job_sub:<ID>` `job:<ID>`（主・第2職業の両方）、`title:<称号名>`
- 職業 ID：木こり `lumberjack`、鉱夫 `miner`、農家 `farmer`、鍛冶師 `blacksmith`、料理人・調合師 `cook`、
  エンチャント師 `enchanter`、釣り師 `fisher`

**連携 → 本体（scriptevent、内容は JSON）**
- `portal:escrow` `{questId, xuid, amount}`：依頼主から預かる
- `portal:payout` `{questId, xuid, amount}`：受注者へ支払う
- `portal:refund` `{questId, xuid, amount}`：依頼主へ返す
- `portal:quest_update` `{quest}`：依頼の状態変化（本体のゲーム内掲示板が使う）
- `portal:quest_reset` `{}`：サイトが全件を返したので、本体の依頼一覧を作り直す
- `portal:status` `{online}`：依頼の取得のたびに送る（本体は「連携パックが動いているか」の判断に使う）
- `portal:quest_create_failed` `{requestId, xuid, status}`：ゲーム内で出した依頼をサイトが受け付けなかった

**本体 → 連携（scriptevent）**
- `portal:result` `{questId, op, ok, reason?}`：上の指示の結果（`reason` は `insufficient` / `unknown_player` / `coin_cap`）
- `portal:delivered` `{questId, xuid}`：受注者の納品を確認した
- `portal:town` `{level, deliveries, facilities}`：街の状態が変わった
- `portal:quest_create` `{requestId, ownerXuid, title, item, qty, reward}`：ゲーム内で依頼を出した（ここで追加した約束事）
- `portal:quest_action` `{questId, action, xuid}`：ゲーム内で受注（`accept`）・取消（`cancel`）した（ここで追加した約束事）

## 本体アドオン側でやること（実装済み）

本体アドオン（CoopTown_BP）には、次の内容を **すでに追加済み**です（`scripts/portal-bridge.js` と `game-engine.js`）。

1. 職業・レベル・所持金・称号を、上のスコアボードとタグへ書き写す
   （本体の保存先はダイナミックプロパティなので、別のパックからは読めないため）
2. `portal:escrow` / `payout` / `refund` を受けてお金を増減し、`portal:result` を返す
   - 同じ `questId`＋操作は1回だけ実行し、記録はワールドに保存（再起動しても重複しない）
   - オフラインのプレイヤーのお金も扱える（本体の保存先はワールド単位のため）
3. 受注者がゲーム内の掲示板で納品したら、素材を持ち物から受け取り、依頼主の受取箱へ届けて `portal:delivered` を送る
4. 街の状態が変わったら `portal:town` を送る
   - 街は「合計512個ごとにレベルアップ」なので、各素材の `need` には次のレベルまでの合計目標（共通）を入れています
   - `facilities` は、今の街のレベルで使える共同施設の名前
5. ゲーム内の依頼掲示板をサイトと一本化
   - 連携パックが動いているとき（5分以内に返事があるとき）は、サイトの依頼を表示します。
     出す・受注・取消はサイトへ送り、お金は上の指示で動きます。
   - 連携パックがないときは、今までどおりゲーム内だけの掲示板として動きます。
   - 以前のゲーム内だけの依頼は「（旧）」として表示し、今までどおり取消・納品できます。
   - サイトの依頼の素材名がゲームのアイテム名（例「丸石」）と一致しないときは、ゲーム内では納品できません。

## Discord への投稿

ゲームの出来事を、Discord のチャンネルに自動で投稿します（サイトは使いません）。

1. Discord で、投稿したいチャンネルの「チャンネルの編集」→「連携サービス」→「ウェブフック」→「新しいウェブフック」を作り、
   「ウェブフック URL をコピー」します。
2. BDS の `config/default/variables.json` に `discord_webhook_url` を追加します。
   ```json
   {
     "portal_url": "https://xxxx.m-ws.cc",
     "discord_webhook_url": "https://discord.com/api/webhooks/xxxx/yyyy"
   }
   ```
   - Webhook の URL は `secrets.json` には入れられません（secrets の値は通信のヘッダーにしか使えないため）。
     URL を知っている人は誰でもそのチャンネルに投稿できるので、人に見せないでください。
3. BDS を起動し直すと、「🟢 サーバーが起動しました」と投稿されます。

投稿する内容（`discord_events` で選べます。書かなければ全部）：

| 名前 | 内容 |
|---|---|
| `server` | サーバーが起動した |
| `join` / `leave` | 参加・退出 |
| `death` | 死亡（原因・倒した相手） |
| `chat` | チャット（`!link` の入力は投稿しません） |
| `levelup` | プレイヤーのレベルが上がった（1分ごとに確認） |
| `quest` | 新しい依頼の掲示、依頼の達成 |

- 5秒ごとにまとめて1つのメッセージで投稿します（Discord の投稿回数の制限のため）。失敗したら後でもう一度送ります。
- `@everyone` などのメンションは効かないようにしてあります。

## 動作確認の手順

1. サイトのマイページで連携コードを出し、ゲーム内で `!link コード` を入力
   → 「Discord『…』と連携しました」と出て、チャットにはコードが表示されない。サイトを再読み込みすると連携済み。
2. 1分以内に、サイトのプレイヤー一覧に自分が出て、レベル・職業・所持金が表示される。
3. ウシに近づく・ゾンビを倒す → 30秒以内に、サイトの個人図鑑に登録される。
4. サイトで報酬100の依頼を作成 → 30秒ほどで依頼主の所持金が100減り、「報酬100コインを預かりました」と出る。
5. 別の人がサイト（またはゲーム内の掲示板）で受注 → ゲーム内の掲示板から納品
   → 依頼が `done` になり、受注者の所持金が100増える（1回だけ）。
6. 依頼主が `open` の依頼を取り消す → 依頼主に100戻る（1回だけ）。
7. サイトを休止させる（または `variables.json` の URL を一時的に間違える）→ ゲームは止まらず、
   復旧後に未送信の分が送られる。
8. サーバーを再起動しても、依頼の支払い・返金が重複しない。

## 開発用のテスト

`tests/` に、両方のパックを偽のサイトにつないで上の 1〜8 をまとめて確かめるテストがあります（ゲームは不要、Node.js で実行）。

```
cd tests
node --import ./register.mjs portal.test.mjs <CoopTown_BP の scripts フォルダ> <このパックの scripts フォルダ>
```

`PORTAL PASS` と出れば成功です。
